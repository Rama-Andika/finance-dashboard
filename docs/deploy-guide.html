1. Ringkasan dalam satu paragraf

Anda mengetik npm run deploy -- acme-production di komputer pembangun. Skrip memeriksa aturan, membangun aplikasi khusus untuk klien itu, membungkusnya menjadi satu berkas .tgz, lalu mengirimnya ke server lewat SSH. Di server, paket dibuka ke folder rilis baru, paketnya dipasang, database dimigrasi, dan pintasan current dipindah ke rilis baru. Service di-restart, lalu skrip menunggu alamat /health menjawab sehat dengan versi yang baru dipasang. Bila tidak sehat dalam 2 menit, pintasan dikembalikan ke rilis sebelumnya secara otomatis.

Dua hal yang tidak berubah: kode aplikasi tidak pernah membuka file env (laptop: scripts/local.mjs, server: systemd yang mengisinya), dan setiap rilis berdiri sendiri di folder sendiri, jadi berpindah rilis hanya memindahkan satu pintasan.

3. Urutan satu deploy

Langkah demi langkah, dengan kata sederhana

  1. Periksa aturan. Production hanya dari tag vX.Y.Z, commit bersih, jam 22:00 sampai 05:00 menurut jam klien, dan Anda mengetik nama target.Komputer pembangun · gagal = berhenti, tidak ada yang berubah
  2. Bangun dan periksa. build:client untuk CLIENT_ID target, lalu build:ops. Versi dan CLIENT_ID di dist/build-info.json harus cocok, dan semua paket yang di-import server harus ikut terpasang oleh npm ci --omit=dev. Hasilnya dikemas jadi .tgz.Komputer pembangun · gagal = berhenti
  3. Cek server dan ambil kunci. Folder deploy dan file env harus ada. mkdir .deploy.lock memastikan hanya satu deploy berjalan.Server · gagal = berhenti; kunci milik deploy lain tidak disentuh
  4. Unggah dan buka. scp ke releases/.incoming/, tar ke releases/.tmp-<nama>, lalu diberi nama akhir releases/<nama>.Server · gagal = rilis setengah jadi dihapus, kunci dilepas
  5. Siapkan rilis. release.mjs doctor (Node, disk, tar, npm), npm ci --omit=dev, env-check terhadap file env.Server · gagal = rilis dihapus, current tidak berubah
  6. Migrasi database. dash-migrate.mjs membuat tabel dash_* baru bila ada.Server → database · gagal = rilis dihapus, current tidak berubah
  7. Ganti rilis. release.mjs activate: current menunjuk rilis baru, rilis lama menjadi previous. Pemindahan satu langkah (rename), tidak pernah setengah jadi.Server
  8. Restart dan tunggu sehat. sudo -n systemctl restart, lalu health-check.mjs menanyakan /health sampai menjawab ok, dengan versi yang baru, terus-menerus 10 detik (paling lama 120 detik).Server
  9. Selesai atau kembali. Sehat: rilis lama dibersihkan (sisa 5 terbaru plus current dan previous), kunci dilepas. Tidak sehat: rollback ke previous, restart, cek lagi.Server

4. Hasil akhir dan kalau ada yang gagal

Tulisan terakhir Artinya Yang Anda lakukan
DEPLOYED … Rilis baru sehat dan berjalan. Kode keluar 0. Tidak ada.
ROLLED BACK: … Rilis baru tidak sehat; rilis lama sudah berjalan lagi dan sehat. Deploy dianggap gagal (kode keluar 1). Cari sebabnya di log service (journalctl) atau logs-find.mjs, perbaiki, deploy lagi.
ACTION NEEDED: … Rilis baru tidak sehat dan rilis lama juga tidak menjawab, atau pintasan tidak bisa dikembalikan. Sekarang juga: journalctl di server, dan release.mjs list --root <folder>.
FAILED: … Berhenti sebelum ada perubahan di server (aturan, build, server tidak siap, kunci ada), atau rilis baru tidak sehat dan tidak ada rilis sebelumnya. Baca pesannya; kebanyakan menyebut perbaikannya sendiri.
PREPARED … Hanya untuk --prepare-only: rilis terpasang tetapi belum diaktifkan. Buat file env di server dengan perintah init-env yang dicetak.
Kunci tertinggal. Bila deploy terputus di tengah (komputer mati), folder <folder deploy>/.deploy.lock bisa tertinggal dan deploy berikutnya menolak. Pesannya memuat perintah untuk menghapusnya; pastikan dulu tidak ada deploy yang sedang jalan.

Nama folder membawa tiga fakta: klien, lingkungan, dan port. Skrip deploy membacanya dari root di file target, dan env-check memastikan isi file env sama dengan nama folder. Rilis dari komputer pembangun tidak membawa node_modules; server memasangnya sendiri (butuh akses ke registry npm).

8. Perintah yang akan Anda pakai

Perintah Fungsi
npm run deploy -- <target> --dry-run Menerapkan aturan dan mencetak setiap langkah tanpa membangun, mengirim, atau mengubah apa pun.
npm run deploy -- <target> --prepare-only Deploy pertama sebuah deployment: memasang rilis tanpa mengaktifkan, supaya init-env.mjs ada di server.
npm run deploy -- <target> Deploy penuh.
npm run deploy -- <target> --status Daftar rilis (mana current, mana previous) dan satu pertanyaan ke /health.
npm run deploy -- <target> --rollback Kembali ke rilis sebelumnya dengan tangan. Dua kali berarti maju lagi.
npm run deploy -- --list-targets [--env staging] Mendaftar target dari env/deploy-targets.json.
npm run build:client -- <id> lalu npm run build:ops Membangun sendiri (urutan penting: yang pertama mengosongkan dist/).
npm run smoke:build Memeriksa hasil build tanpa database.
npm run env:check -- <file> Memeriksa file env.

Opsi lain: --force-window (darurat, production di luar jendela), --skip-build, --allow-dirty (hanya staging), --keep <n>, --yes.

9. Aturan production

  • Tag. Hanya dari tag vMAJOR.MINOR.PATCH yang menunjuk persis ke commit yang dibangun: git tag v1.2.3 lalu git push origin v1.2.3. Staging boleh dari commit mana saja.
  • Jendela. 22:00 sampai 05:00 menurut jam setempat klien (zona waktu di file target). Pukul 22:00 boleh, pukul 05:00 tidak.
  • Konfirmasi. Anda mengetik nama target (misalnya acme-production).
  • Migrasi tambah-saja. Hanya tabel baru atau kolom baru yang boleh kosong. Jangan menghapus, mengganti nama, atau mengubah tipe kolom yang masih dibaca rilis sebelumnya.
  • Satu klien pada satu waktu. Mulai dari satu klien percobaan, pantau sampai hari kerja berikutnya, baru lanjut. Bila bermasalah: --rollback klien itu dan hentikan.
Belum teruji di server nyata: ssh/scp sungguhan, sudo systemctl, nginx, npm ci di server, dan migrasi sungguhan. Alur dan alat server sudah dites dengan tiruan dan dengan alat asli di folder sementara. Kerjakan staging lebih dulu. Persiapan server baru (sudoers, unit systemd, nginx) ada di docs/project-guide.md bab 10.9.3.

10. Istilah

Istilah Arti
Target Satu deployment: satu klien, satu lingkungan, satu server. Namanya <klien>-<env>.
Rilis Satu folder di releases/ bernama <waktu UTC>-<versi>.
current / previous Pintasan (symlink) ke rilis yang berjalan dan rilis sebelumnya.
Rollback Memindahkan current kembali ke previous, lalu restart.
Health check Alamat <awalan>/health yang menjawab status, versi, dan kondisi database.
Kunci deploy Folder .deploy.lock di server; mencegah dua deploy bertabrakan.
CLIENT_ID Nama deployment yang ditanam saat build (awalan alamat) dan dipakai server. Staging: <klien>-staging.
APP_ENV development, staging, atau production. Wajib, tanpa nilai bawaan.
systemd Pengatur layanan Linux: menyalakan aplikasi, menyalakannya lagi bila mati, dan memberinya isi file env.
